# peanuts：在询问它任何问题之前先喂饱大象

## 它解决什么问题

在大型遗留代码库中，AI 智能体无法一开始就理解整个系统。上下文窗口有限，而代码库可能很大。当智能体需要理解代码库以设计或实现功能时，它会被淹没在无关代码中。

`peanuts` 通过让智能体从叶子目录开始构建 README 文件来解决这个问题，然后逐步向上合并到更高级别的目录中。这创建了一个自底向上的文档树，智能体（和人类）可以使用它来理解系统，而无需阅读所有源代码。

## 它如何触发

当用户提到以下内容时，此技能激活：
- 引导文档
- 理解代码库
- README 文件
- "这个代码库是如何组织的"
- "我需要一个代码库的概述"

## SKILL.md 逐节解析

### Frontmatter

```yaml
name: peanuts
description: 当用户想要为大型遗留代码库引导文档时，构建一个自底向上的 README 文件树，每个级别都带有人工审查关卡。当用户提到 README、文档结构、理解代码库或引导时使用此技能。
```

- **name** — 技能的短名称
- **description** — 触发器词和技能功能的摘要

### 正文

正文分为四个步骤：

1. **找到叶子目录** — 识别代码库中没有子目录的目录
2. **人工审查关卡** — 在每个叶子 README 之后暂停进行人类审查
3. **合并到父目录** — 将子 README 向上合并到父目录
4. **重复到根目录** — 一直向上，直到到达根目录

每个步骤都指定了智能体应该做什么、输入是什么、输出是什么。

## SKILL.md 之外的内容

- `assets/readme-templates.md` — README 文件的模板

### Evals

- `evals/trigger-evals.json` — 触发测试，验证描述是否在应该激活时激活

## 工作示例

假设你有一个代码库，结构如下：

```
src/
├── auth/
│   ├── login.py
│   └── logout.py
├── api/
│   ├── users.py
│   └── posts.py
└── main.py
```

`peanuts` 会：

1. 从 `auth/` 和 `api/` 开始（叶子目录）
2. 为每个目录编写 README
3. 等待人工审查
4. 合并到 `src/`
5. 为 `src/` 编写 README
6. 等待人工审查
7. 合并到根目录

最终输出：

```
src/
├── README.md
├── auth/
│   ├── README.md
│   ├── login.py
│   └── logout.py
├── api/
│   ├── README.md
│   ├── users.py
│   └── posts.py
└── main.py
README.md
```

## 技能与文章的对比

文章描述了引导的概念：从叶子向上构建文档树。技能添加了：
- 每个级别的人工审查关卡
- 具体的 README 模板
- 与 elephant 的接口（根 README 是 Elephant 的输入）
- 触发测试

## 审查问题和练习

1. 为什么 `peanuts` 在叶子目录处暂停进行人工审查，而不是在父目录？如果它只在根目录审查一次，会错过什么？
2. 设计一个 README 模板，适用于你的项目。它是否捕获了 `peanuts` 识别的关键组件？
3. 取一个现有的代码库，手动运行 `peanuts` 的一个级别。你遇到了什么意外？
4. 触发测试包括"near misses"——接近激活但不应该激活的请求。为什么这些很重要？
