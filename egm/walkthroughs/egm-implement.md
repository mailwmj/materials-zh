# egm-implement：构建文档，只构建文档

## 它解决什么问题

当 AI 智能体实现设计时，它经常添加文档中未描述的内容。它"修复"问题、"改进"代码，或添加它认为有用的功能。这些"帮助"的更改累积起来，使代码与文档不同步。

`egm-implement` 通过严格限于文档中明确描述的内容来解决这个问题。它不添加未要求的功能，不优化未请求的代码，也不修复文档中未提及的问题。

## 它如何触发

当用户提到以下内容时，此技能激活：
- 从设计文档实施
- 构建功能
- "将设计转化为代码"
- "从规范编码"

## SKILL.md 逐节解析

### Frontmatter

```yaml
name: egm-implement
description: 当用户想要从已签署的设计文档实施功能时，仅构建设计文档中列出的文件，并在现实与文档不符时停止。
```

- **name** — 技能的短名称
- **description** — 触发器词和技能功能的摘要

### 正文

正文分为五个步骤：

1. **设置** — 创建文件夹、复制模板、读取文档
2. **构建每个文件** — 逐个构建列出的文件
3. **验证实施** — 检查实现是否匹配文档
4. **处理漂移** — 如果发现差异，停止并通知人类
5. **完成** — 标记所有文件已完成

每个步骤都指定了智能体应该做什么、输入是什么、输出是什么。

## 工作示例

假设你有一个签署的设计文档，描述了三个文件。你启动 `egm-implement`：

1. 智能体构建 `file1.py`。
2. 智能体验证 `file1.py` 匹配文档。
3. 智能体构建 `file2.py`。
4. 在验证期间，智能体发现 `file2.py` 需要文档中未描述的辅助函数。
5. 智能体停止，记录漂移到 `IMPLEMENT.md`，并通知你。
6. 你编辑设计文档以包含辅助函数。
7. 你重新运行 `egm-implement`。
8. 智能体继续构建剩余文件。

## 技能与文章的对比

文章描述了实施应该忠实地遵循设计。技能添加了：
- 具体的漂移检测机制
- 账本文件以记录已构建的内容
- 与 mean-review 的接口（实现是审查的输入）
- 触发测试

## 审查问题和练习

1. 为什么 `egm-implement` 在发现漂移时停止，而不是继续构建其他文件？
2. 你能想出一个漂移是合理的场景吗（即，实施需要文档中未描述的内容，但这是一个好的做法）？
3. 如果设计文档有缺陷（如遗漏了一个必要的文件），`egm-implement` 会做什么？
4. 比较 `egm-implement` 与传统的"实现用户故事"方法。主要区别是什么？
