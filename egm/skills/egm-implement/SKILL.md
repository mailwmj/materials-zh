# egm-implement

仅构建设计文档中列出的文件，并在现实与文档不符时停止。

## 何时激活

当用户满足以下条件时激活此技能：
- 想要从设计文档实施功能
- 提到从设计文档实施、从规范编码或从设计构建
- 有来自 goldfish 的已签署设计文档
- 使用诸如"实现此设计"、"构建此功能"、"将设计转化为代码"、"从规范编码"等短语

当用户想要审查设计文档（使用 goldfish）、审查代码（使用 mean-review）或设计新功能（使用 elephant）时，不要激活此技能。

## 执行步骤

### 步骤 1：设置

1. 创建一个新的 docs/egm/<slug>/ 文件夹（如果不存在）
2. 将 implement-ledger-template.md 复制到 docs/egm/<slug>/IMPLEMENT.md
3. 读取 docs/designs/<slug>.md 以了解要构建的内容
4. 如果存在，读取 goldfish 账本（docs/egm/<slug>/GOLDFISH.md），以了解签署决策

### 步骤 2：构建每个文件

按照设计文档中的实施计划，逐个构建每个列出的文件。

对于每个文件：
1. 检查设计文档中的文件规范
2. 构建文件以匹配规范
3. 将实施细节记录到 IMPLEMENT.md

### 步骤 3：验证实施

在每个文件构建后，智能体应验证：
- 文件是否实现了文档中描述的功能？
- 实施是否与文档中描述的接口匹配？
- 是否有任何假设需要文档中未描述的内容？

### 步骤 4：处理漂移

如果在验证期间发现漂移（实施需要文档中未描述的内容，或文档中的描述与实际实施不匹配）：

1. **停止** — 不要继续构建更多文件
2. 将漂移记录到 IMPLEMENT.md
3. 通知人类存在漂移
4. 等待人类修复设计文档

这是关键的纪律：当现实与文档不符时，技能会停止。它不会绕过差异或"猜测"正确的行为。

### 步骤 5：完成

当所有文件都构建完成且没有漂移时：
1. 更新 IMPLEMENT.md 以标记所有文件已完成
2. 运行设计文档中描述的任何测试
3. 将控制权交还给人类进行审查

## 输出

- 实施文件（代码）
- `docs/egm/<slug>/IMPLEMENT.md` — 记录已构建的内容和任何漂移的账本文件

## 与 mean-review 的接口

egm-implement 的输出是 mean-review 的输入。审查技能将审查实施的差异，以查找代码中的问题。

这就是为什么严格遵守文档很重要：审查技能信任实施遵循设计。如果实施添加了未描述的内容，审查可能无法正确评估它。
