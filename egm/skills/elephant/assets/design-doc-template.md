# 设计文档模板

此模板由 elephant 技能使用，用于生成四部分设计文档。

## 模板

```markdown
# <功能名> 设计文档

> **slug**: <slug>  
> **日期**: <YYYY-MM-DD>  
> **作者**: <作者名>

## 背景

<为什么我们做这个？它解决什么问题？>

<提供足够的上下文，以便不熟悉项目的读者理解动机。>

## 需求

<这个功能必须做什么？>

### 功能需求

- <需求 1>
- <需求 2>
- <需求 3>

### 非功能需求

- <性能、安全性、可用性等要求>

### 成功标准

<我们如何知道这个功能是否成功？>

- <标准 1>
- <标准 2>

## 设计

<这个功能如何工作？>

### 架构概述

<高层架构描述，包括关键组件及其关系。>

### 组件

#### <组件 1>

<此组件的描述。>

- **职责**: <它做什么>
- **接口**: <它暴露的接口>
- **依赖**: <它依赖什么>

#### <组件 2>

...

### 数据流

<数据如何流经系统？>

```
<流程图或序列描述>
```

### 数据模型

<关键数据结构。>

```
<模式定义或数据结构描述>
```

### 边界情况

<关键边界情况和失败模式如何处理？>

- <边界情况 1>: <处理方式>
- <边界情况 2>: <处理方式>

## 计划

<我们如何构建这个？>

### 实施步骤

1. **步骤 1**: <描述>
   - 文件: `<文件路径>`
   - 验证: <如何验证此步骤>

2. **步骤 2**: <描述>
   - 文件: `<文件路径>`
   - 验证: <如何验证此步骤>

### 里程碑

- **里程碑 1**: <描述> — <日期>
- **里程碑 2**: <描述> — <日期>

### 风险和缓解措施

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| <风险> | <高/中/低> | <如何缓解> |

## 附录

<任何不适合其他部分的附加信息。>
```

## 使用说明

- 将所有占位符（尖括号中的文本）替换为实际内容
- 删除不需要的部分
- 添加与你的功能相关的部分
- 确保文档是自包含的：一个新的 AI 会话应该能够理解它，无需额外的上下文
