# peanuts

为大型代码库构建自底向上的 README 文件树，每个级别都带有人工审查关卡。

## 何时激活

当用户满足以下条件时激活此技能：
- 提到为代码库引导文档
- 想要理解大型遗留代码库
- 需要目录的 README 文件
- 使用诸如"这个代码库是如何组织的"、"这个目录是做什么的"、"我需要文档"等短语

当用户想要设计新功能（使用 elephant）、审查代码（使用 mean-review）或从设计文档实施（使用 egm-implement）时，不要激活此技能。

## 执行步骤

### 步骤 1：找到叶子目录

在目标代码库中找到所有叶子目录（没有子目录的目录）。

对于每个叶子目录：
1. 读取目录中的所有文件
2. 编写一个 README.md，描述：
   - 此目录的用途
   - 主要文件及其作用
   - 关键函数、类或组件
   - 与其他目录的关系
3. 将 README 保存到 README.md
4. 暂停进行人工审查

### 步骤 2：人工审查关卡

在每个叶子 README 编写完成后，暂停并等待人工审查。

人工应检查：
- README 是否准确描述了代码？
- 是否识别了关键组件？
- 语言是否清晰且适合其他智能体阅读？

如果 README 不准确，与智能体讨论并修复。在 README 可靠之前不要继续。

### 步骤 3：合并到父目录

一旦叶子 README 可靠，就向上移动到父目录。

对于父目录：
1. 读取所有子目录的 README
2. 读取父目录中的文件
3. 编写一个 README.md，描述：
   - 此目录的用途
   - 子目录及其作用
   - 父目录中的主要文件
   - 此目录如何适应更大的系统
4. 将 README 保存到 README.md
5. 暂停进行人工审查

### 步骤 4：重复到根目录

重复步骤 3 和 4，一次向上一级，直到到达代码库的根目录。

最终输出是根目录中的一个 README.md，它总结了整个系统。

## 输出

- 每个目录中的 README.md
- 根目录中的 PEANUTS.md — 记录哪些目录已完成、审查决策以及任何未解决的问题的账本文件

## 与 elephant 的接口

peanuts 的输出是 elephant 的输入。当 elephant 技能启动时，它读取根 README.md 以了解系统架构，然后开始设计对话。

这就是为什么人工审查关卡至关重要：如果 README 不准确，elephant 将从错误的假设开始。
