# peanuts

为大型代码库构建自底向上的 README 文件树，每个级别都带有人工审查关卡。

## 何时激活

当用户满足以下条件时激活此技能：
- 提到为代码库引导文档
- 想要理解大型遗留代码库
- 需要目录的 README 文件
- 使用诸如"这个代码库是如何组织的"、"这个目录是做什么的"、"我需要文档"等短语

当用户想要设计新功能（使用 elephant）、审查代码（使用 mean-review）或从设计文档实施（使用 egm-implement）时，不要激活此技能。

## 执行步骤

### 步骤 1：找到叶子目录

在目标代码库中找到所有叶子目录（没有子目录的目录）。

对于每个叶子目录：
1. 读取目录中的所有文件
2. 编写一个 README.md，描述：
   - 此目录的用途
   - 主要文件及其作用
   - 关键函数、类或组件
   - 与其他目录的关系
3. 将 README 保存到 README.md
4. 暂停进行人工审查

### 步骤 2：人工审查关卡

在每个叶子 README 编写完成后，暂停并等待人工审查。

人工应检查：
- README 是否准确描述了代码？
- 是否识别了关键组件？
- 语言是否清晰且适合其他智能体阅读？

如果 README 不准确，与智能体讨论并修复。在 README 可靠之前不要继续。

### 步骤 3：合并到父目录

一旦叶子 README 可靠，就向上移动到父目录。

对于父目录：
1. 读取所有子目录的 README
2. 读取父目录中的文件
3. 编写一个 README.md，描述：
   - 此目录的用途
   - 子目录及其作用
   - 父目录中的主要文件
   - 此目录如何适应更大的系统
4. 将 README 保存到 README.md
5. 暂停进行人工审查

### 步骤 4：重复到根目录

重复步骤 3 和 4，一次向上一级，直到到达代码库的根目录。

最终输出是根目录中的一个 README.md，它总结了整个系统。

## 输出

- 每个目录中的 README.md
- 根目录中的 PEANUTS.md — 记录哪些目录已完成、审查决策以及任何未解决的问题的账本文件

## 与 elephant 的接口

peanuts 的输出是 elephant 的输入。当 elephant 技能启动时，它读取根 README.md 以了解系统架构，然后开始设计对话。

这就是为什么人工审查关卡至关重要：如果 README 不准确，elephant 将从错误的假设开始。

## 提示词

`peanuts` 使用 `peanuts` 提示词来指导智能体构建 README 文件。提示词告诉智能体：

- 如何识别叶子目录
- 如何编写 README
- 何时暂停进行人工审查
- 如何向上合并到父目录

## 示例

假设你有一个代码库，结构如下：

```
src/
├── auth/
│   ├── login.py
│   └── logout.py
├── api/
│   ├── users.py
│   └── posts.py
└── main.py
```

`peanuts` 会：

1. 从 `auth/` 和 `api/` 开始（叶子目录）
2. 为每个目录编写 README
3. 等待人工审查
4. 合并到 `src/`
5. 为 `src/` 编写 README
6. 等待人工审查
7. 合并到根目录

最终输出：

```
src/
├── README.md
├── auth/
│   ├── README.md
│   ├── login.py
│   └── logout.py
├── api/
│   ├── README.md
│   ├── users.py
│   └── posts.py
└── main.py
README.md
```

## 限制

- `peanuts` 只创建 README 文件。它不设计功能、不审查代码、不实施更改。
- 人工审查关卡是强制的。不要跳过它们。
- README 质量取决于智能体对代码的理解。如果代码混乱，README 也会混乱。

## 如果 Python 不可用

如果 Python 不可用，手动执行相同操作：使用 `git ls-files` 列出目录，从最深到最浅排序，然后在汇总之前检查每个父目录的子目录。
