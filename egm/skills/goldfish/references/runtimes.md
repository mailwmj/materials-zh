# Goldfish 运行时

此参考资料描述了 goldfish 技能支持的运行时环境。

## 并行执行

Goldfish 技能设计为并行运行三个审查者。这显著减少了审查时间，因为三个会话同时工作，而不是顺序运行。

### 支持的运行时

| 运行时 | 并行支持 | 说明 |
|--------|----------|------|
| Aider | 是 | 使用 `--message` 或 API 调用启动多个实例 |
| Claude Code | 是 | 使用多个终端窗口或后台进程 |
| OpenAI Codex | 是 | 使用多个终端窗口或后台进程 |
| 自定义脚本 | 是 | 使用 subprocess 或 API 调用 |

### 如果并行不可用

如果并行执行不可用，可以顺序运行三个审查者。这需要更长时间（大约三倍），但产生相同的结果。

顺序运行时，确保：
- 每个审查者在新的会话中启动（无上下文残留）
- 在启动下一个审查者之前保存前一个审查者的报告
- 在收集所有三个报告之前不要进行分析

## 提示词管理

每个审查者使用不同的提示词（见 `goldfish-reviewer-prompts.md`）。这些提示词应保持不变，以确保审查的一致性。

如果修改提示词：
- 确保所有三个审查者仍然使用不同的角色
- 测试修改后的提示词是否产生一致的审查质量
- 记录更改和理由

## 报告聚合

收集所有三个报告后，人类负责：

1. 分类每个问题为实质性或琐碎
2. 聚合跨审查者的发现（如果多个审查者报告相同的问题）
3. 决定是修复设计还是重新运行审查

## 限制

Goldfish 审查有以下限制：
- 审查者只能看到设计文档，不能看到实施代码
- 审查者没有 Elephant 对话的上下文
- 审查质量取决于设计文档的清晰度
- 如果设计文档模糊，审查者可能会错过问题或报告误报

## 与 harness 的集成

不同的 AI harness 以不同的方式支持技能。Goldfish 技能需要能够启动三个全新的 AI 会话。

### Claude Code

Claude Code 支持斜杠命令。你可以使用 `/goldfish` 启动技能。对于并行审查，你需要启动三个独立的 Claude Code 实例。

### Aider

Aider 没有技能加载器，因此你需要手动启动三个 Aider 会话。每个会话应该是一个全新的 `aider` 进程，从未见过你的设计聊天。

### 自定义 harness

如果你正在构建自己的 harness，你需要：
1. 读取 `SKILL.md` frontmatter 以了解何时激活技能
2. 将技能正文附加到系统提示词中
3. 提供一种启动全新会话的方法（用于并行审查）
