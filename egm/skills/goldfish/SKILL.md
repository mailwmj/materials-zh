# goldfish

并行将设计文档发送给三个全新审查者，并循环直到只剩琐碎修改。

## 何时激活

当用户满足以下条件时激活此技能：
- 想要审查设计文档
- 提到金鱼、全新审查者或全新视角
- 需要验证设计文档是自包含的
- 使用诸如"审查我的设计"、"这个设计清晰吗"、"别人能理解这个吗"、"设计审查"等短语

当用户想要创建设计文档（使用 elephant）、从设计文档实施（使用 egm-implement）或审查代码（使用 mean-review）时，不要激活此技能。

## 执行步骤

### 步骤 1：设置

1. 创建一个新的 docs/egm/<slug>/ 文件夹（如果不存在）
2. 将 goldfish-ledger-template.md 复制到 docs/egm/<slug>/GOLDFISH.md
3. 读取 docs/designs/<slug>.md 以了解待审查的内容
4. 如果存在，读取 elephant 账本（docs/egm/<slug>/ELEPHANT.md），以了解设计决策

### 步骤 2：启动三个审查者

并行启动三个全新的 AI 会话（如果并行不可用，则顺序启动）。

每个会话：
1. 只接收设计文档（docs/designs/<slug>.md）
2. 不接收 elephant 对话上下文
3. 根据其分配的角色审查文档
4. 生成审查报告

审查者角色：
- **审查者 A** — 关注功能正确性和需求覆盖
- **审查者 B** — 关注架构质量和设计模式
- **审查者 C** — 关注边缘情况、失败模式和风险

### 步骤 3：收集报告

人类收集所有三个报告。对于每个报告：

1. 将问题分类为：
   - **实质性** — 需要设计或实施更改的问题
   - **琐碎的** — 措辞、格式或澄清问题
2. 在 GOLDFISH.md 中记录分类
3. 汇总所有三个审查者的发现

### 步骤 4：处理实质性修改

如果有任何实质性修改：
1. 人类编辑 docs/designs/<slug>.md 以解决这些问题
2. 更新 GOLDFISH.md 以记录已解决的问题
3. 返回步骤 2（重新运行审查）

### 步骤 5：签署或跳过

当所有三个会话只报告琐碎修改时：
1. 人类审查琐碎修改列表
2. 对于每个琐碎修改，决定是否值得修复
3. 签署设计文档（或记录跳过-单独）
4. 更新 GOLDFISH.md 以记录签署决策

## 输出

- `docs/designs/<slug>.md` — 已签署的设计文档（可能已编辑）
- `docs/egm/<slug>/GOLDFISH.md` — 记录审查发现和签署决策的账本文件

## 与 egm-implement 的接口

goldfish 的输出是 egm-implement 的输入。实施技能将读取已签署的设计文档并仅构建文档中描述的内容。

这就是为什么签署至关重要：实施技能信任设计文档是准确的。如果设计未经审查，实施可能会构建错误的东西。

## 提示词

`goldfish` 使用 `goldfish-reviewer-prompts.md` 中的提示词来指导三个审查者。每个审查者有不同的角色，以确保全面的覆盖。

## 示例

假设你已完成 `elephant` 并有一个设计文档。你启动 `goldfish`：

1. 三个全新会话并行启动。
2. 审查者 A 发现：需求 #3 没有成功标准。
3. 审查者 B 发现：组件 X 和 Y 之间的接口没有定义。
4. 审查者 C 发现：如果服务 Z 失败，没有回退策略。
5. 人类修复所有三个问题。
6. 重新运行审查。
7. 审查者只报告琐碎修改（如"将此句子改为主动语态"）。
8. 人类签署设计文档。

## 限制

- `goldfish` 只审查设计文档。它不实施代码、不运行测试、不修复问题。
- 审查者只看到设计文档，没有 Elephant 对话的上下文。
- 如果设计文档模糊，审查者可能会报告误报或错过问题。

## 并行执行

`goldfish` 设计为并行运行三个审查者。这显著减少了审查时间，因为三个会话同时工作，而不是顺序运行。

### 支持的运行时

| 运行时 | 并行支持 | 说明 |
|--------|----------|------|
| Aider | 是 | 使用 `--message` 或 API 调用启动多个实例 |
| Claude Code | 是 | 使用多个终端窗口或后台进程 |
| OpenAI Codex | 是 | 使用多个终端窗口或后台进程 |
| 自定义脚本 | 是 | 使用 subprocess 或 API 调用 |

### 如果并行不可用

如果并行执行不可用，可以顺序运行三个审查者。这需要更长时间（大约三倍），但产生相同的结果。

顺序运行时，确保：
- 每个审查者在新的会话中启动（无上下文残留）
- 在启动下一个审查者之前保存前一个审查者的报告
- 在收集所有三个报告之前不要进行分析
