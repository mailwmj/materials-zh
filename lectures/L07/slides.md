# 请求对象

```json
POST {base_url}/chat/completions

{
  "model": "qwen3.5:9b",
  "messages": [
    {"role": "system",    "content": "..."},
    {"role": "user",      "content": "..."},
    {"role": "assistant", "content": "..."},
    {"role": "user",      "content": "..."}
  ],
  "stream": true
}
```

<div class="caption mt-4">这是你的程序与模型之间的完整接口。</div>

<!--
就是它。一个 HTTP POST，一个 JSON 对象。这是你所构建的一切与模型之间的完整接口。

`model` 是服务器知道的标识符，原样发送。你在 Aider 配置中一直输入的 `ollama_chat/` 前缀是 Aider 的路由，不是模型的名称，你的规范在配置部分说明了这一点。

`messages` 是实验课 01 中的堆栈，编码为一个列表。你的系统提示是第一条。你选择的文件，F3，在一条消息内部，因为看看这个对象：没有文件的字段。没有其他地方可以放它们。历史记录是每一次更早的完整回合。你最新的消息在最后。

幻灯片上没有的一件事。`Authorization: *** 且仅当设置了 `api_key` 时。没有密钥意味着完全没有该头部，不是空头部，因为 Ollama 会拒绝空头部。而且该密钥永远不会出现在错误消息、日志行或提交中。

[暂停。] 现在看看这个对象中没有什么东西。有件事你已经被告知两次了，它不在这里。是什么？

说明：在最后一行暂停，让观众回答后再前进。他们已经被告知两次没有任何东西被记住。
-->

# 另外三个请求字段

- `temperature` — L02 的采样步骤，带一个刻度盘
- `max_tokens` — 一个上限，也是测试的最佳朋友
- `tools` — 今天的后半部分

<div class="caption mt-6">省略 <code>temperature</code>，服务器会自己选。它选的不是零。</div>

<!--
你刚才看到的对象是最小值。还有三个字段，它们还没有在讲座中出现过。

`temperature` 是 L02 的采样步骤，带一个刻度盘。L02 说模型在整个词汇表上计算一个分布并从中采样。这个数字在采样之前缩放该分布。接近零时，最可能的 token 几乎每次都赢。更高时，尾部被选中的频率更高。

如果你不发送它，服务器选择一个默认值，而默认值不是零。在第 7 周，你的评估工具链会在任何可能的地方想要 temperature 为零，这样三次运行一项任务产生差异是因为任务而不是骰子。即使在零时，它们在每个服务器上也不会完全相同。

第 1 阶段不要求你发送它。你的设计文档应该说明你是否发送。

`max_tokens` 限制回复。它是使测试确定性的廉价方法，在两页幻灯片中，我将故意用它来破坏某个东西。

`tools` 是今天的后半部分。
-->

# "兼容"承诺什么

- Ollama、llama.cpp、vLLM、每个供应商：相同的对象
- 没有人批准它。一个供应商的 API 赢了
- 在推理、工具、`usage` 处 fray

<div class="caption mt-6"><code>ENDPOINT.md</code> 画出了界限：文本聊天补全，仅此而已。</div>

<!--
关于为什么这能工作的一段话。

Ollama 接受这个对象。llama.cpp 的服务器也接受，vLLM 也接受，每个商业供应商也都接受。没有人批准这一点。一个供应商的 HTTP API 成为了所有人复制的形状，而这个形状现在比供应商本身更有价值。这就是为什么 L01 可以告诉你模型是一行配置并且是认真的。

它在边缘 fray，你会在今天遇到每一个边缘。模型的推理在哪里到达因服务器而异。工具调用是整体到达还是片段到达因服务器而异。流上是否显示 usage 取决于一个服务器发明而其他服务器复制的字段。

`ENDPOINT.md` 画出了界限：文本聊天补全，仅此而已。越过这条线，你需要在服务前放一个代理，而不是更改你的代码。

<div class="label">每个回复都有一个结束原因</div>

# 三个结束原因

|| 值 | 你的程序的义务 ||
|---|---|
|| `stop` | 模型结束了它。F5 可能会寻找编辑块 ||
|| `length` | 被截断了。一个明确的错误，永远不是编辑 ||
|| `tool_calls` | 它在请求。后半部分 ||

<div class="caption mt-6">给你的代码的信息，不是给用户的。</div>

<!--
每个回复都有一个结束原因，而原因是一个字段。你会看到三个值，阅读第二列：每一个都是对你的程序的义务，不是给用户的状态行。

`stop` 意味着模型结束了自己的回复。这是 F5 被允许去寻找编辑块的唯一值。

`length` 意味着它被截断了。

`tool_calls` 意味着它在向你要东西。后半部分。

<!--

[运行命令 2。]

内容是一个空字符串。reasoning 字段是 8 个 token 长。模型不是什么都没说；服务器在思考中途截断了它。

# 你的估算器评分的依据

```text
"usage": {"prompt_tokens": 31, "completion_tokens": 465, "total_tokens": 496}
```

- `/tokens` 预测。这个字段计数了
- 发送一次，比较，校准。一个下午

<div class="caption mt-6">F1 允许估算粗略。它不允许它未校准。</div>

<!--
服务器为你计数了。31 个 token 输入，465 个输出。

你的 `/tokens` 命令显示一个估算，而 F1 允许这个估算粗略。一个固定的字符-per-token 比率是可以的，只要它是确定性的。

这个字段是该估算被测量所依据的地面真实值。发送一个请求，将 `prompt_tokens` 与 `/tokens` 预测的进行比较，调整你的比率。这就是整个校准，它是一个下午的工作，不是一个项目。

`ENDPOINT.md` 告诉你偏高估算。原因是四页幻灯片之后。

测量在这个模型上，2026-09-22：一个空的用户消息花费 10 个 prompt token。"Hi" 花费 11。"Explain TCP in detail." 花费 16，同样的句子两次花费 21。所以这十六个中的六个是单词，十个是一个固定的底层，聊天模板的角色标记和回合分隔符，在每个消息发送给模型之前添加。

这个底层是一个字符-per-token 估算器看不到的：它计数字符串，从不计数脚手架，因此它低估了每个请求，而且错误随着历史增长。另一个偏高的原因。把这个放在口袋里而不是屏幕上；它是某人总是问的问题的答案。
-->

# 一个回复作为事件

```text
data: {"choices":[{"delta":{"role":"assistant","content":"","reasoning":"Thinking"}}]}
data: {"choices":[{"delta":{"content":"","reasoning":" Process"}}]}
...

data: {"choices":[{"delta":{"content":" server"}}]}
data: {"choices":[{"delta":{},"finish_reason":"stop"}]}
data: [DONE]
```

<div class="caption mt-4">一句话，516 个事件。大多数根本不携带文本。</div>

<!--
`ENDPOINT.md` 说 `stream` 在第 1 阶段始终为 true，F1 说回复在片段到达时打印。所以这里又是同一个问题，流式传输。

[运行命令 3。让它滚动。]

回来的是什么不是一个 JSON 对象。它是服务器发送事件：每个事件一个 `data:` 行，它们之间有一个空行，相同的信封，`message` 变成了 `delta`。

[显示计数。] 五百一十六个事件。一句话。其中大多数携带了一个推理片段和一个空内容。

你的回复是每一个内容增量的串联，由你组装。模型按顺序写了它。没有任何东西告诉你顺序是完整的，除了结束原因和 sentinel。
-->

# 六种事件

|| 事件 | 携带 ||
|---|---|
|| 开头增量 | `role`。这里，还有一个推理片段 ||
|| 仅推理增量 | 思考。数百个 ||
|| 内容增量 | 用户看到的文本 ||
|| 空增量 | `finish_reason` ||
|| 仅 usage 事件 | 根本没有 `choices` ||
|| `[DONE]` | 不是 JSON。正常结束 ||

<!--
六种，你的客户端接受所有这些而不抱怨。`ENDPOINT.md` 的要接受的东西列表就是这个列表，上面的每一行都是某人已经发布的一个 bug。

开头增量宣布角色。在这个捕获上，它还携带了第一个推理片段，所以它不是空的；在一个不推理的模型上，它将是角色和一个空内容。无论哪种方式，它都不包含答案文本。然后是仅推理增量，数百个。内容增量，用户看到的那些。一个携带结束原因的空增量。一个 usage 事件，里面根本没有 `choices`，如果你要求了的话。以及 `[DONE]`，它不是 JSON，也是唯一告诉你流正常结束的东西。

最后一个让许多人措手不及。一个客户端对每一个 `data:` 行调用 `json.loads`，在最后一行上会死掉。
-->
