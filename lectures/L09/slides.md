<div class="label">规范 2.4</div>

# 六个停止条件

|| 条件 | 捕获 ||
|---|---|
|| 任务完成 | 模型发出完成的信号 ||
|| 步骤限制 | 明显的失控 ||
|| token 预算 | 增长的上下文 ||
|| 挂钟 | 挂起的命令 ||
|| 重复调用 | 永远相同的调用 ||
|| 连续错误 | 失去线索的运行 ||

<!--
这是规范的列表，第 2.4 节，它是你实验课 03 的清单。规范说你需要所有六个，而且每个在运行日志中需要一个不同的退出原因。

把它读作一个加五。第一行是我们刚刚花了十分钟的那个。任务完成是你想要的出口：运行结束是因为工作完成，以你定义的方式。其他五个是限制。每一个结束运行是因为一个数字达到了，在限制上结束的运行没有完成。所以当我说六个停止条件时，我的意思是完成，加上五个限制。

现在将右列读作一个链。步骤限制是明显的那个：它捕获失控。规范通过上面的那些遗漏的内容证明下一个两个。token 预算存在是因为步骤限制没有捕获上下文在增长的循环。挂钟存在因为那些中的任何一个都没有捕获挂起的命令。最后两个是关于模型的行为而不是运行的大小：永远相同的调用，这是小模型卡住的最常见方式，以及它没有从中恢复的一串错误。

两件事对所有五个都成立。每一个在日志中得到它自己的名称，因为"停止"将告诉你什么都没有当你下周阅读日志时。而且每一个有一个你选择的数字。规范没有为你选择它。

接下来的五页幻灯片一个一个带它们。对于每一个：其他放过的运行，以及你必须写下的一个决策。
-->

# token 预算

- L07：九步中 471 到 3252 token
- 一个大读取：一步中 +10,000
- 在请求发出之前检查
- **你的决定：** 下一个请求，还是运行总计？

<!--
步骤限制没有捕获一个上下文在增长的循环。L07 的提示在九步中从 471 token 到 3252，七倍。那其中的九步是无害的。一个大型 read_file，或一个输出是完整测试日志的 run_command，在一个步骤中增加一万，而步骤限制没有注意到。

在请求发出之前检查它：最后回复的 prompt token，加上它的 completion token，加上你附加以来的估算。usage 是来自 L07 的地面真实值，所以第一次之后的每个检查都锚定在一个真实数字上。

两个数字用这个名字通过，所以选一个。下一个请求的大小保护上下文窗口，这就是 2.4 的意思。运行中的总计保护你的钱包。在周四的 Toolkit 密钥上那是真钱：黑客松 README 说花掉全部二十五美元的方法是一个没有步骤限制的模型循环。在一个本地模型上，它是时间。

v0 没有压缩。当大小检查触发时，运行结束。它不总结并继续。

<div class="label">条件 4</div>

# 挂钟

- `flask run`，一个观察者，`git commit` 的编辑器
- 没有请求，所以没有步骤，没有 token
- 每个命令超时，加上一个运行预算
- 标准输入关闭

<!--
那些中的任何一个都没有捕获挂起的命令。模型运行一些永远不会退出的东西。没有新请求出去，所以没有步骤被计数，没有 token 被花费。

候选人是普通的。监视模式的测试运行器。git commit 打开一个编辑器。等待标准输入的命令。在一个有 Flask 前端的仓库中， aider-practice 从第 11 到第 16 课有，flask run，一个模型测试其 web 更改会启动而且从不返回。

在步骤之间检查的运行级时钟无法中断那些中的任何一个，因为循环卡在 execute 内部。所以挂钟是两个机制：每个命令和每个模型请求的超时，以及整个运行的预算。在每个命令上关闭标准输入，stdin 情况变成一个即时错误而不是挂起。

一个警告，因为它在幻灯片上。关闭标准输入修复读取标准输入的程序。它不修复一个编辑器。git commit 没有消息打开一个，而且一个编辑器可以直接与终端对话而不是读取标准输入，所以它仍然可以坐在那里等待。对于那个情况，每个命令超时是结束它的东西，或者你在命令的环境中设置 GIT_EDITOR=true，所以 git 从不打开一个编辑器。
-->

# 重复相同调用

- 相同：工具名称加上解析的参数
- 写入后的重复是进步
- 精确匹配错过 L07 的步骤 8 和 9

<!--
最常见的小模型失败：同样的调用，永远。它读取一个文件，不在它上面行动，并再次读取它。

"相同"需要一个定义。将工具名称和排序键的解析参数与原始参数字符串进行比较，其中空白不同。

然后决定一个重复是否总是一个循环。在修复后再次运行 pytest 是工作进展良好。在写入之间没有任何东西再次运行它是循环。在调用和其结果上键入，或在任何写入上重置计数，你可以区分它们。

注意精确匹配错过什么。L07 的步骤 8 和 9 都删除了任务列表，而且它们不相同：一个以 python -c 结尾，另一个以 python cli.py add 结尾。

# 连续工具错误

- 连续：任何成功重置它
- 无法运行：一个错误
- 运行并退出 1：**你的决定**

<!--
模型失去了线索，没有从中恢复。错误是结果，规范 2.1，所以模型每次被告知，而且连续几个可以是模型纠正自己。连续很多个不是。计数是连续的，被任何成功重置。

什么算作一个错误是决定。一个工具不能做被请求的事是一个：没有这样的文件，一个被其超时杀死的命令，不是有效 JSON 的参数。

<!--

# `/undo` 回退什么

|| 调用 | `/undo` ||
|---|---|
|| `write_file taskr/cli.py` | 回退它 ||
|| `rm -f ~/.taskr.json` | 什么都没有：从未被跟踪 ||
|| `git reset --hard` | 什么都没有：git 是网 ||
|| `pip install ...` | 什么都没有：不是你的仓库 ||
|| `curl ... \| sh` | 什么都没有：别人的程序 ||

<!--
Apply 的安全网是每个编辑的提交和 /undo。它足够了，因为 Aider 更改的唯一东西是你的仓库中的文件，而且 git 跟踪那些。

第一行：对跟踪文件的写入。Undo 回退它。这就是它的用途。

其他一切。rm 主目录中的一个文件：git 从未知道它。git reset --hard 或 git clean：它摧毁了 git 正在保护的未提交工作。pip install：它改变了你的 Python，不是你的仓库。curl piped to sh：它作为你运行别人的程序。

设计文档的规则是一句话。审批与工具一起 shipped，在同一周，因为 git 不覆盖 bash。你的第 1 阶段文件保护停留。它们将 write_file 限制在仓库中。它们对 shell 字符串什么也不做。
-->
